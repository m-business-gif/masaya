# サロンボード クーポン自動並び替え

直近の来店実績（売上明細でクーポンが使われた実績）があるクーポンを、サロンボードの表示順で上位に自動的に並び替えるスクリプトです。

## ステータス：GitHub Actions（クラウド）からは現状動作しません

2026/09/16 の検証で、salonboard.com が GitHub Actions のようなクラウド/データセンターの
IPアドレスからのアクセスに**応答を返さない**（TCP接続・TLSハンドシェイクまでは成功するが、
HTTPリクエスト送信後に無応答のままタイムアウト）ことを確認しました。ボット対策（Akamai等）
によるものとみられます。ID/パスワード（Secrets）は正しく設定されていても、この通信の壁の
せいで自動化は失敗します。

そのため、`.github/workflows/salon-board-coupon-reorder.yml` の**毎週自動実行は無効化**して
あります（`workflow_dispatch` による手動実行のみ残しています）。将来、自宅PCなどを
[self-hosted runner](https://docs.github.com/actions/hosting-your-own-runners) として
登録すれば、そこから実行することで回避できる可能性があります（未検証。Playwrightの自動操作
自体が別途ボット判定される可能性は残ります）。

現状の運用は、このリポジトリの自動化ではなく、毎週月曜朝にリマインダー通知を送る方式に
切り替えています（詳細はユーザーとのやり取り参照）。

## 重要：使い始める前に

1. **サロンボードの利用規約を確認してください。** 本スクリプトはサロンボードに実際にログインし、
   画面を自動操作（ブラウザ自動化）します。自動化ツールでのアクセスが規約上問題ないか、
   事前にご自身で確認してください。
2. **セレクタは画面のスクリーンショットから推測したもので、実機での動作確認はまだ済んでいません。**
   `config/selectors.json` に `REQUIRES_VERIFICATION` はもう残っていない（＝一見動きそうに見える）
   状態ですが、これは「実際に動かして確認した」ことを意味しません。**必ず最初は DRY_RUN で試し、
   ログの内容（どのクーポンを何位から何位に変更する予定か）が正しいか目視確認してから、
   本番実行（`DRY_RUN=false`）に切り替えてください。**
3. **最初は必ず DRY_RUN で試してください。** 誤った並び替えが本番のクーポン表示に反映されるのを防ぐため、
   `DRY_RUN=true`（デフォルト）では実際の保存・反映申請を行わず、変更予定をログ出力するだけです。

## ルール

- 直近 `LOOKBACK_DAYS`（デフォルト7日＝直近1週間）に来店実績（会計）があったクーポンを表示順の上位にまとめます。
  「売上管理」＞「売上明細」画面を来店日で絞り込み、カテゴリが「クーポン」を含む行から判定します。
- 各グループ（実績あり／なし）の中では、元の表示順を維持します（不要な入れ替えを避けるため）。
- ログインしているアカウントが管理する**全サロン**を自動的に処理します（サロン一覧から取得）。
- `config/excluded-salons.json` に記載した名前を含むサロンは対象から除外されます（部分一致）。
  現在は以下を除外設定済みです。
  - 目黒
  - 【小顔・痩身】小顔専門店Lift(リフト)調布（旧：most eyes 調布）

## セットアップ

```bash
cd salon-board-coupon-sync
npm install
npx playwright install --with-deps chromium
cp .env.example .env   # .env に実際のID/パスワードを設定（絶対にコミットしないこと）
```

## セレクタの検証方法

サロンボードの画面構造（HTML）は実際にログインしないと確認できません。以下の手順で
`config/selectors.json` を埋めてください。

1. `npm run codegen` を実行すると、Playwright Inspector が起動しブラウザが開きます。
2. 実際にログイン画面・予約一覧画面・クーポン管理画面を操作すると、右側にセレクタ入りのコードが
   自動生成されます。
3. 生成されたセレクタを `config/selectors.json` の対応する項目に反映してください
   （ロジック本体 `src/*.js` は変更不要です）。
4. 特に以下を確認してください。
   - ログイン成功後に表示される、ログイン失敗時には出ない要素（`login.successIndicator`）
   - 売上明細画面の「検索期間」の日付入力欄2つ（`salesDetail.dateFromInput` / `dateToInput`）。
     テキスト直接入力かカレンダーピッカー必須かで実装（`src/sales.js`）の調整が必要な場合があります。

## ローカルでの試し方

```bash
npm run reorder:dry-run   # 実際の保存なし。ログで変更予定を確認
npm run reorder           # .env の DRY_RUN=false の場合のみ実際に保存
```

## GitHub Actions での運用

1. リポジトリの Settings → Secrets and variables → Actions で以下を設定してください。
   - `SALON_BOARD_LOGIN_ID` (Secret)
   - `SALON_BOARD_PASSWORD` (Secret)
   - `SALON_BOARD_DRY_RUN` (Variable, 任意): セレクタ検証・動作確認が終わるまでは `true` のままにし、
     問題ないことを確認できたら `false` に変更してください。未設定時は安全側の `true` として動作します。
   - `SALON_BOARD_LOOKBACK_DAYS` (Variable, 任意): デフォルト `7`
2. Actions タブから「サロンボード クーポン自動並び替え」を `workflow_dispatch` で手動実行し、
   `dry_run: true` の状態でログを確認してから、定期実行（毎週月曜 06:00 JST）に任せてください。
3. 失敗時はエラー画面のスクリーンショットが Artifacts にアップロードされます。

## 売上ダッシュボード（ローカル専用）

サロンボードの売上明細から、自分専用の売上ダッシュボードをローカルPCで見られる機能です。
以下の5画面で構成されます。

1. サマリー（今月の売上・客数・客単価、前月比、目標達成率、低パフォーマンス店舗アラート）
2. スタッフ分析（個人売上ランキング、オプション売上率、物販売上率）
3. メニュー分析（メニュー別売上構成、クーポン別売上、オプション販売状況）
4. 物販分析（商品別売上、回数券販売状況、美容液など物販内訳）
5. 客数・稼働分析（新規・再来推移、予約経路別集客、時間帯別来店数、スタッフ別対応件数）

クーポン自動並び替えと同じ理由（salonboard.comがクラウドIPからのアクセスに応答しない）で、
データ取得はローカルPCから実行する必要があります。

### 事前準備：追加セレクタの検証

詳細エクスポートでは、既存のクーポン並び替え機能では使っていない列（来店日・スタッフ名・金額・
客区分・予約経路）を売上明細画面から取得します。これらは実機未検証のため、
`config/selectors.json` の `salesDetail.exportColumns` は初期状態では
すべて `REQUIRES_VERIFICATION`（プレースホルダ）のままになっています。

1. `npm run codegen` で売上明細画面を実際に操作し、該当する列のセレクタを確認する。
2. `config/selectors.json` の `salesDetail.exportColumns` に実際のセレクタを反映する。
3. 埋め終わるまでは `npm run export:sales` はエラーで停止します（誤ったデータで
   集計してしまうのを防ぐための安全装置です）。

既存のクーポン自動並び替え機能（`npm run reorder`）は、この検証状況に関わらずそのまま動作します。

### 使い方

```bash
# お試し：ダミーデータで画面だけ先に確認する
npm run dashboard:mock
npm run dashboard:serve
# ブラウザで http://localhost:3000 を開く

# 実データで使う（上記のセレクタ検証が完了してから）
npm run export:sales
npm run dashboard:serve
```

`config/targets.json` にサロンごとの月次売上目標（円）を設定すると、サマリー画面で
目標達成率としきい値未達アラートが表示されます（未設定の場合は「目標未設定」表示）。

### 制約・注意事項

- 客数・稼働の指標は、来店実績（明細行の日付・スタッフ・時刻の組み合わせ）から推定した
  参考値です。お客様名までは取得していないため、同時刻に同じスタッフが複数人を担当した
  場合などは正確に区別できません。「スタッフ別対応件数」も実際の勤務時間ではなく、
  施術件数ベースの参考値です。
- 月の途中に確認した場合、前月比は「月末までの前月実績」と「月初からの今月実績」の
  単純比較になるため、実際より悪化して見えます（画面にも注記が出ます）。
- グラフ描画には Chart.js（CDN配信）を使用しているため、閲覧時にインターネット接続が
  必要です。読み込めない場合は自動的に表データのみの表示に切り替わります。

## 既知の制約

- サロンボードには公式APIがないため、UI変更で本スクリプトが壊れる可能性があります。壊れた場合は
  `npm run codegen` でセレクタを取り直してください。
- 「来店実績とクーポンの紐付け」は売上明細画面の「メニュー・店販」列に表示されるクーポン名をそのまま
  突き合わせています。クーポン名の表記ゆれ（全角/半角、末尾の空白など）がある場合は一致しないことが
  あるため、必要に応じて `src/sales.js` / `src/coupons.js` の比較ロジックに正規化処理を追加してください。
- 売上明細は複数ページにまたがる場合、「次へ」ボタンを自動でクリックして全ページを走査します。
